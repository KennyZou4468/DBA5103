# 种植模块：资源平衡与工具状态建模笔记

> 更新日期：2026-11-14。本文记录当前讨论中的种植模块 MILP 变量、参数和约束。工具升级的完整状态转移与服务期约束见同目录的 `种植模块_最优化问题与约束_审核稿.md` 第 5 节。

## 1. 时间口径和集合

- 规划日：\(t\in\{1,\ldots,T\}\)。
- 作物：\(c\in\mathcal C\)。
- 工具等级：\(i\in\{0,1,2,3\}\)，依次为 Basic、Copper、Steel、Gold；当前种植模块不纳入 Iridium。
- 工具类型：\(j\in\{H,W\}\)，分别为锄头和水壶。
- 当日支出在日初支付；收获收入在日末结算，并于下一日可用。
- 土地状态 \(S_t\) 定义为第 \(t\) 天的整地、种植和收获均完成后，仍空闲且可立即再种的耕地格数。因此，同日收获的格子允许同日重新种植。
- 新种作物当天需要浇水；最后一次收获当天不需浇水；再生作物的中间收获日仍需浇水。
- 每季首日（\(t\in\{1,29,57,85\}\)）先清除上一季的空闲已整地格；允许跨相邻可种季节存活的作物继续占用其原格并在之后收获。
- 水壶补水、田地坐标和升级工具的覆盖形状不显式建模；补水不消耗模型资源，且覆盖能力默认可以充分利用。

## 2. 决策变量和派生量

| 符号 | 类型 | 定义 |
| --- | --- | --- |
| \(X_{c,t}\in\mathbb Z_{\ge0}\) | 决策变量 | 第 \(t\) 天新种下作物 \(c\) 的格数。 |
| \(L_t\in\mathbb Z_{\ge0}\) | 决策变量 | 第 \(t\) 天新增整地格数。 |
| \(S_t\in\mathbb Z_{\ge0}\) | 状态变量 | 第 \(t\) 天结束后空闲、可种的耕地格数。 |
| \(l_{i,t}\in\mathbb Z_{\ge0}\) | 决策变量 | 第 \(t\) 天用等级 \(i\) 锄头整地的格数。 |
| \(w_{i,t}\in\mathbb Z_{\ge0}\) | 决策变量 | 第 \(t\) 天用等级 \(i\) 水壶浇水的格数。 |
| \(H^{\mathrm{crop}}_t\ge0\) | 派生量 | 第 \(t\) 天所有收获动作对应的作物格数；再生作物的每次收获均计入。 |
| \(F_t\ge0\) | 派生量 | 第 \(t\) 天收获后真正释放的土地格数；再生作物仅最后一次收获计入。 |
| \(W_t\ge0\) | 派生量 | 第 \(t\) 天必须浇水的作物格数。 |
| \(TS_t\ge0\) | 派生量 | 第 \(t\) 天种植模块总耗时。 |
| \(PS_t\ge0\) | 派生量 | 第 \(t\) 天种植模块总体力消耗。 |
| \(Money_t\ge0\) | 状态变量 | 第 \(t\) 天日初可用现金。 |

工具升级沿用审核稿中的变量：\(U^j_{i,t}\) 表示把等级 \(i-1\) 升至 \(i\) 的决策；\(S^j_{i,t}\) 表示工具 \(j\) 的当前精确等级；\(Z^j_{i,t}\) 表示等级 \(i\) 的工具 \(j\) 当日实际可用；\(D^j_t\) 表示工具 \(j\) 是否处于服务期。为避免与土地状态 \(S_t\) 混淆，工具状态始终带上上标 \(j\)。

## 3. 由数据预先生成的批次参数

对每个“作物 \(c\) 于第 \(s\) 天种植”的批次，构建下列已知 0--1 参数：

\[
h_{c,s,t}=1
\quad\Longleftrightarrow\quad
\text{该批作物在第 }t\text{ 天收获}.
\]

\[
f_{c,s,t}=1
\quad\Longleftrightarrow\quad
\text{该批作物在第 }t\text{ 天最后一次收获并释放土地}.
\]

\[
w^{\mathrm{need}}_{c,s,t}=1
\quad\Longleftrightarrow\quad
\text{该批作物在第 }t\text{ 天仍在地里且按项目口径需要浇水}.
\]

这些是参数而非变量。`crop_harvest_schedule.csv` 已提供 \((c,s,t)\) 的收获事件和收获序号，可直接生成 \(h\)；每个批次收获序号最大的事件生成 \(f\)。\(w^{\mathrm{need}}\) 由作物成长／再生日程、季节和最后收获日生成。

`scripts/build_crop_daily_events.py` 已将三者物化为 `crop_daily_events.csv`（长表字段为 `crop_key, plant_day, calendar_day, needs_water, is_harvest, releases_land`），并由 `scripts/build_final_model_data.py` 纳入 `data/final/baseline_inputs/planting/`。实现应读取该表，不应在优化模型内部重新判断成长、收获或浇水逻辑。

## 4. 作物批次、土地和浇水需求

所有收获动作：

\[
H^{\mathrm{crop}}_t=
\sum_{c\in\mathcal C}\sum_{s\le t}h_{c,s,t}X_{c,s}.
\]

当天释放的土地：

\[
F_t=
\sum_{c\in\mathcal C}\sum_{s\le t}f_{c,s,t}X_{c,s}.
\]

当天需要浇水的格数：

\[
W_t=
\sum_{c\in\mathcal C}\sum_{s\le t}w^{\mathrm{need}}_{c,s,t}X_{c,s}.
\]

土地平衡：

\[
\boxed{
S_t=(1-\delta_t)S_{t-1}+L_t+F_t-\sum_{c\in\mathcal C}X_{c,t}
}
\]

\[
S_0=0,
\qquad S_t\ge0.
\]

其中 \(\delta_t=1\) 当且仅当 \(t\in\{1,29,57,85\}\)，否则为 0。该式在季首日丢弃上一季空闲耕地，但不影响跨季存活作物：它们不属于 \(S_{t-1}\)，并继续由批次事件参数产生之后的浇水和收获事件。再生作物的中间收获会增加 \(H^{\mathrm{crop}}_t\) 和销售收入，但不增加 \(F_t\)，因此不会错误释放土地。

## 5. 工具可用性和按等级分配的格数

所有新整地格数必须由某个可用等级的锄头完成：

\[
\sum_{i=0}^{K}l_{i,t}=L_t,
\qquad
l_{i,t}\le M_L Z^H_{i,t}.
\]

所有需要浇水的格数必须由某个可用等级的水壶完成：

\[
\sum_{i=0}^{K}w_{i,t}=W_t,
\qquad
w_{i,t}\le M_W Z^W_{i,t}.
\]

取 \(M_L=M_W=642=\lfloor900/1.4\rfloor\)，即一天只进行一种每格农务时可处理的最大格数。若工具送修，则所有对应 \(Z^j_{i,t}=0\)，上式自动使整地或浇水变量归零。播种本身不使用锄头或水壶，因此不应额外加入 \(X_{c,t}\le M\sum_i Z_{i,t}\)；其可行性已由土地平衡限制。

## 6. 时间与体力

采用数据中“每格平均成本”的口径。`planting_tool_catalog.csv` 是锄头与水壶系数的唯一来源：所有等级的 `time_game_minutes_per_unit` 均为 1.40；`energy_per_unit` 依等级读取（Basic／Copper／Steel／Gold 水壶为 1、0.33、0.20、0.11；锄头为 2、0.67、0.40、0.22）。令 \(\bar\tau^H_i\)、\(\bar e^H_i\) 分别为等级 \(i\) 锄头每整一格的时间和体力；\(\bar\tau^W_i\)、\(\bar e^W_i\) 为等级 \(i\) 水壶每浇一格的时间和体力；\(\tau^P=1.4\)、\(\tau^R=1.4\) 为每格播种与收获时间。

\[
TS_t=
\sum_i\bar\tau^H_i l_{i,t}
+\tau^P\sum_cX_{c,t}
+\sum_i\bar\tau^W_i w_{i,t}
+\tau^R H^{\mathrm{crop}}_t.
\]

\[
PS_t=
\sum_i\bar e^H_i l_{i,t}
+\sum_i\bar e^W_i w_{i,t}.
\]

\[
TS_t\le900,
\qquad
PS_t\le270.
\]

上述写法只含“固定参数 \(\times\) 决策变量”。不要先令工具成本等于 \(\sum_i C_iZ_{i,t}\)，再把它乘以总格数；后者会形成变量乘变量。

## 7. 现金

令 \(p_c\) 为种子单价、\(r_{c,s,t}\) 为 `crop_daily_events.csv` 中该批作物在第 \(t\) 天每格收获收入（字段 `base_revenue_g_per_tile_harvest`；非收获日为 0），\(\kappa_i\) 为升级至等级 \(i\) 的现金等价费用。\(\kappa_i\) 从 `planting_tool_catalog.csv` 的 `upgrade_cash_equivalent_cost_g` 读取，包含黑匠费用和所需金属锭的普通售价；本模块不维护金属锭库存。当天日初支出为：

\[
Pay_t=
\sum_cp_cX_{c,t}
+\sum_{j\in\{H,W\}}\sum_{i=1}^{3}\kappa_iU^j_{i,t}.
\]

日初资金必须覆盖当天支出：

\[
Money_t\ge Pay_t.
\]

收获收入应按批次和收获事件计入：

\[
Revenue_t=
\sum_{c\in\mathcal C}\sum_{s\le t}
r_{c,s,t}X_{c,s}.
\]

资金递推为：

\[
Money_{t+1}=Money_t-Pay_t+Revenue_t,
\qquad Money_1=500.
\]

固定规划期为 112 天，种植独立模块的目标函数为：

\[
\max\;Money_{113}.
\]

## 8. 已确定范围与后续验证

1. 当前不设置农场地图格数上限；土地只受整地、浇水、时间和体力限制。
2. 当前工具范围止于 Gold，不设置 Iridium 升级变量或参数行。
3. 作物成长、再生、跨季存活、最后收获和浇水区间均以 `crop_daily_events.csv` 为唯一求解器输入；该表由脚本从种植日历和收获日程生成。
4. 水壶补水、田地坐标和蓄力覆盖形状均为已接受的简化；覆盖能力默认可充分利用。
5. 后续实现阶段应以小规模日期范围测试土地、现金、服务期、收获与浇水事件的平衡关系，再扩展至完整 112 天。
