# 钓鱼模块 数据使用指南

## 数据用途

本指南说明钓鱼模块如何读取地点、季节、时段与钓鱼等级对应的鱼池平均价值。日常实现优先读取 `data/final/baseline_inputs/fishing/` 与 `data/final/baseline_inputs/shared/`。基础版不在活动过程中临时抽取鱼，而是事先把所有可能的鱼和非鱼结果汇总为每竿平均收入。

## 数据读取顺序

1. 实现当前基础版时，核心读取 `fishing_solver_parameters.csv`、`fishing_time_blocks.csv`、`fishing_experience_rules.csv`、`fishing_experience_levels.csv`、`fishing_equipment_catalog.csv`、`fishing_equipment_modes.csv` 和共享目录中的 `global_parameters.csv`。
2. 每天开始时，按截至前一天的累计已结算抛竿数查 `fishing_experience_levels.csv`，得到当天的 `fishing_level`；再用该等级、地点、季节与时段查询 `fishing_solver_parameters.csv`。
3. 当天每一次已结算抛竿都增加 1 次经验。鱼、藻类／果冻、海藻和垃圾一律同样计数；当天新增次数只从次日改变等级。
4. `fishing_rod_catalog.csv` 记录购买价格、等级门槛和槽位。等级 2 与等级 6 分别使玻璃纤维鱼竿和铱金鱼竿可在次日购买；Standard Bait、Spinner 和 Dressed Spinner 已可实际使用。
3. 如需查看鱼、藻类、果冻和垃圾如何构成某个平均值，到 `data/final/complete_tables/` 读取对应的结果明细或概率覆盖表。
4. 如需重新计算概率或复核精确期望值，以 `data/canonical/` 的同名表为准；它是唯一保留完整计算精度的权威层。
5. `data/display/` 仅用于人工阅读，不能作为程序输入；`data/source/` 仅保存 Wiki 页面和游戏解包资料。

## 必读数据

| 文件 | 数据粒度 | 关键字段 | 游戏含义 |
| --- | --- | --- | --- |
| `global_parameters.csv` | 全局参数 | 每日时间、每日体力、全年天数 | 每天可钓鱼的总范围。 |
| `fishing_time_blocks.csv` | 四个大时段 | 时段起止、持续分钟 | 说明一天划分为哪些钓鱼时间段。 |
| `fishing_solver_parameters.csv` | 等级 × 地点 × 季节 × 时段 | 平均每竿金币、体力、等待时间、可用状态 | 基础版选择地点和时段时的完整每竿活动参数。 |
| `fishing_timing_rules.csv` | 钓鱼时间规则 | 等待时间的原始依据 | 审计 21.9 游戏分钟的来源，不必在求解时另行读取。 |
| `fishing_experience_rules.csv` | 经验计数规则 | 每次结算抛竿的经验、何时生效 | 固定“每竿 1 次”的简化口径。 |
| `fishing_experience_levels.csv` | 等级 0–10 | 累计抛竿门槛、对应原版 XP、解锁鱼竿 | 把累计次数映射为当天的钓鱼等级。 |
| `fishing_equipment_catalog.csv` | 鱼饵／吊钩目录 | 价格、门槛、耐久、效果和基础版状态 | 仅 `active` 的三种装备可以进入当前求解。 |
| `fishing_equipment_modes.csv` | 可用装备组合 | 所需鱼竿、等级、每竿鱼饵、鱼饵等待时间倍率与吊钩耐久 | 定义六种可查的每竿参数模式；`0.5` 表示鱼饵将等待时间减半。 |
| `fishing_locations.csv` | 地点目录 | 地点 ID 和名称 | 审计五个公共钓点。 |
| `fishing_rod_catalog.csv` | 鱼竿 | 价格、购买门槛、鱼饵／鱼钩槽位、基础版状态 | Fiberglass Rod 与 Iridium Rod 分别是已启用鱼饵和吊钩的装备前置。 |

当前钓鱼安排的七个核心输入是 `fishing_solver_parameters.csv`、`fishing_time_blocks.csv`、`fishing_experience_rules.csv`、`fishing_experience_levels.csv`、`fishing_equipment_catalog.csv`、`fishing_equipment_modes.csv` 和共享目录中的 `global_parameters.csv`。第一项已经包含各等级、装备模式下各地点、季节与时段的每竿期望收益、体力、等待时间、鱼饵成本和吊钩耐久消耗；`fishing_timing_rules.csv` 仅保存这些时间与体力变化的 Wiki 依据。

## 使用步骤

1. 读取四个时段及其长度，并以累计抛竿数确定当天开始时的等级。
2. 根据等级、已拥有鱼竿、装备模式、当天所在季节、地点和时段，查找平均每竿金币、体力和等待时间。
3. 只使用 `ready_for_solver=yes` 的记录。
4. 选择 `bait` 模式时，每竿购买并消耗 1 个标准鱼饵，计入 5g 成本；选择 Spinner 或 Dressed Spinner 时，须已拥有铱金鱼竿。
5. 吊钩每捕到 20 条鱼后损耗。求解器使用参数表中“每竿预期吊钩消耗量”，即该条件下鱼类概率除以 20；非鱼结果不损耗吊钩。
6. 对当天所有已结算抛竿累加 1 次经验，并在次日重新确定等级。
5. 使用结果表核验平均收入已经包含鱼与非鱼结果；不要重新逐项相加。

## 字段解释与注意事项

- 平均每竿金币代表长期重复钓鱼的平均回报，不代表每一竿固定卖出该金额。
- 鱼种数量更多不等于平均收益更高，必须看预计算的平均每竿金币。
- 时段系数已整合时段内部的鱼类出现边界，不能只按时段开始时刻判断鱼池。
- 当前等级会改变鱼类最低等级筛选、原版基础上钩概率、每竿体力和等待时间，因此 `fishing_level` 是求解器查询参数表时不可省略的键。
- 经验不是原版按鱼种、品质、完美捕获与宝箱计算的 XP，而是用户确定的“每次已结算抛竿 = 1 次”替代状态。
- `bait_waiting_time_multiplier` 直接表示鱼饵对咬钩等待时间的倍率：无鱼饵为 `1.0`，使用 Standard Bait 为 `0.5`，即最小和最大等待时间均减半。Spinner 与 Dressed Spinner 分别将最大等待再减少 5.4 与 10.7 游戏分钟。所有求解器时间字段均为游戏分钟。
- 其余吊钩完整保留在目录，但在“100% 成功、普通品质、无宝箱收益”的当前口径下没有可审计的货币效益，禁止进入装备模式。
- 概率表保留计算精度；展示时才转成一位小数百分比。

## 最小检查

- 无装备结果覆盖 11 个等级、五个地点、四季和四个时段，共 880 个组合；加入等级门槛后的六种装备模式共形成 2,880 条求解器参数。
- 四个时段总长度为 900.0 游戏分钟。
- 每竿平均金币和体力均非负。
- 任一结果明细组合中的概率合计应为 1.0，允许极小计算误差。

运行 `python3 scripts/validate_data_package.py` 可执行完整数据包检查。
