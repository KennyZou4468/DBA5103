# 钓鱼模块：数据使用指南

本文件说明当前仓库中实际存在的输入及其读取口径。数学式见 [完整模型](钓鱼模块_完整设定与数学模型_更新版.md)，分类检查与联动见 [审核说明](钓鱼模块_约束审核与联动接口.md)。

## 1. 目录与读取顺序

从仓库根目录读取 `fishing/data/` 的钓鱼参数与 `shared/data/global_parameters.csv`。当前仓库不含原完整包中的 `canonical/`、`complete_tables/`、`source/` 等目录，不能把这些历史路径写进运行脚本并假定文件存在。

1. 读取共享日历、初始现金和每日预算。
2. 读取四时段和等级门槛，确定日期的季节映射及次日生效规则。
3. 读取鱼竿、有效装备目录和六种模式，建立等级资格与鱼竿兼容关系。
4. 读取活动参数，只保留 `ready_for_solver=yes` 的行，按日期扩展有效集合 Ω。
5. 在 MILP 内用累计竿数识别等级，再以等级和持有状态启用活动；不要在外部预设每天钓满或固定等级路径。
6. 由选中的活动计算毛收入、成本、时间与体力，接入同一现金平衡。

## 2. 输入表与模型职责

| 文件 | 粒度或主要内容 | 在模型中的用途 |
| --- | --- | --- |
| `shared/data/global_parameters.csv` | 全局参数 | 500g、900 游戏分钟、270 体力、112 天；本次不改共享文件 |
| `fishing_solver_parameters.csv` | 等级×模式×地点×季节×天气×时段 | v、τ、e、β、δ 的主输入 |
| `fishing_time_blocks.csv` | 四个时段 | H 与窗口；以 duration 字段作为分钟长度 |
| `fishing_experience_levels.csv` | 等级 0-10 | 累计已结算竿数门槛 a |
| `fishing_experience_rules.csv` | 计数与生效规则 | 每结算一竿加 1，次日改变等级 |
| `fishing_rod_catalog.csv` | 五种鱼竿目录 | 只启用 Bamboo、Fiberglass、Iridium；价格、门槛和槽位 |
| `fishing_equipment_catalog.csv` | 消耗品目录 | 仅 active 的 Bait、Spinner、Dressed Spinner 有效 |
| `fishing_equipment_modes.csv` | 六种组合 | 最低等级、鱼饵消耗、吊钩类别与鱼竿能力 |
| `fishing_locations.csv` | 五个地点 | 地点名称、标识和可用日期 |
| `fishing_timing_rules.csv` | 原始计时与体力依据 | 单位与来源审计；不在求解中重复调整已处理时间 |

除第一行外，表格文件均位于 `fishing/data/`。鱼竿目录中的 `active_eligible_purchase` 表示已启用、仍需资格和现金的可选购买，不表示初始拥有。来源链接、快照路径、审核状态和说明字段是元数据，不是状态变量。

## 3. 主键与系数字段

主键为 `fishing_level + equipment_mode_id + fishing_location_id + season + weather + time_block_id`，必须唯一。每天的 season 由日期决定，weather 固定为 sunny；等级由 N(t-1) 决定。

| 字段 | 单位 | 使用方法与常见错误 |
| --- | --- | --- |
| `expected_g_per_cast` | g/竿 | 毛收入已含鱼和非鱼；不能再加一次结果收益，也不能当净收入 |
| `expected_waiting_time_game_minutes_per_cast` | 游戏分钟/竿 | 已含等级与装备效果；不再次减半或扣吊钩时间 |
| `expected_energy_per_cast` | 体力/竿 | 保留小数，等于 8−0.1×等级 |
| `bait_units_per_cast` | 个/竿 | 含鱼饵为 1，否则 0；用于数量核对 |
| `bait_gold_cost_per_cast` | g/竿 | 直接计支出，含鱼饵为 5，否则 0 |
| `expected_fish_nibbles_per_cast` | 概率 | 鱼类总概率；非鱼也计经验，但不耗吊钩 |
| `expected_tackle_items_consumed_per_cast` | 预期枚数/竿 | 含吊钩时为鱼类概率/20；再乘该类吊钩单价 |
| `hook_success_rate` | 比例 | 当前固定 1；不能据此把毛收入或经验再调整一次 |
| `ready_for_solver` | 标记 | 仅表示参数准备状态；不代替等级、现金和鱼竿资格 |

## 4. 模式与兼容性必须一起判断

| 模式 | 最低等级 | 合法持有关系 |
| --- | --- | --- |
| `none` | 0 | 初始 Bamboo 即可 |
| `bait` | 2 | 拥有 Fiberglass 或 Iridium |
| `spinner`, `bait_spinner` | 6 | 拥有 Iridium |
| `dressed_spinner`, `bait_dressed_spinner` | 8 | 拥有 Iridium |

`required_rod_id=fiberglass_rod` 在纯 bait 行表示最低所需鱼竿，不是唯一指定鱼竿。应使用明确兼容集合 `{fiberglass_rod, iridium_rod}`，不能让仅拥有 Iridium 的玩家被迫先买 Fiberglass 才能只装鱼饵。

参数表已通过是否存在该等级模式行落实最低等级；如果代码自行生成完整笛卡尔积，则必须额外禁用无效组合，不允许给缺失系数填 0。

## 5. 成长、消耗与现金

- 每竿结算后 N 增加 1，不乘鱼类概率；所有结果均计数。
- 当天等级只读 N(t-1)。累计 30、254、531 次分别打开次日等级 2、6、8，不再额外延后一天。
- 持有状态用 own(t)=own(t−1)+buy(t)，当日购买后可用；鱼竿无铁匠停用期。
- 吊钩只计预期耐久摊销，不维护整枚采购与剩余耐久，不追加一笔整枚固定费。
- 当日总支出不能超过开盘现金。仅检查日末现金非负不够，因为钓鱼购竿当天仍可赚钱。
- 若计算净收益，按“毛收入−鱼饵−吊钩摊销−鱼竿”计算；全局不能再扣第二遍。

## 6. 可复查的数据检查

当前参数分布：none 为 880 行，bait 为 720；两种 Spinner 模式各 400；两种 Dressed 模式各 240，合计 2,880 行。每个等级模式应覆盖五地点、四季、四时段，即 80 个组合。

应检查主键唯一、ready 标记、模式等级门槛、鱼竿 ID 与目录一致、所有金额与资源非负、体力公式、鱼饵成本、四时段合计 900，以及含吊钩 δ 与鱼类概率/20 在导出舍入容差内一致。

本次已检查这些内部一致关系，并核对主模型示例的资源与现金算术。尚未运行钓鱼求解器。原 `scripts/validate_data_package.py` 及完整逐结果概率表未提供，不能声称运行过该脚本、验证了每组概率和为 1 或独立重算全部期望收益。

## 7. 给汇总报告的说明

收益、时间与耐久均为期望近似；随机实际游戏不保证获得相同结果。将来结果文件应区分摘要、逐日计划和活动明细，并标明实验、目标、截止日和最优性状态。具体建议字段见审核说明第 7 节。
