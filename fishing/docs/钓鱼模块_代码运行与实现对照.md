# 钓鱼模块：代码运行与实现对照

本实现保留 ZIP 与完整数学规格的基线，不增加旅行、食物、天气抽样、逐鱼 XP、整枚吊钩库存或当日卖鱼融资。只读 fishing/data 与 shared/data，不改写输入文件。

## 1. 安装和运行

需要 Python 3.10 或以上。在仓库根目录执行：

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 改用：.venv\Scripts\Activate.ps1
python -m pip install -r fishing/requirements.txt
python fishing/src/fishing_milp.py --horizon 112 --time-limit 180 --gap 0
python fishing/src/fishing_validate.py fishing/results/baseline_112
python -m unittest discover -s fishing/tests -v
```

默认开源 HiGHS，无需许可证。若需与 planting/mining 一致，另安装 `gurobipy` 并配置足够规模的学术许可证，然后添加 `--backend gurobi`。Gurobi 入口使用同一套系数矩阵；当前提交的实际结果来自 HiGHS，未在 Gurobi 上运行。全年模型约 18,514 个变量，超过 Gurobi 免费受限许可证的常见规模限制。

输出默认写入 `fishing/results/baseline_112/`。试跑可用 `--horizon 2 --out fishing/results/my_trial`，避免覆盖全年结果。所有路径均由脚本位置解析，因此不依赖个人绝对路径。

```bash
# 基线、禁购鱼竿、五个固定地点、一份明确口径的 1/3 资源情景及 LP 上界
python fishing/src/run_fishing_experiments.py --time-limit 180 --gap 0
# 使用已存在且参数哈希一致的基线
python fishing/src/run_fishing_experiments.py --reuse-baseline --time-limit 180 --gap 0
```

1/3 情景将初始现金、每日总体时间与体力同时乘 1/3，保留四个完整钟点窗，再以每日总时间 300 分钟限制。它不同于把每个时段容量也除以 3，不代表已经完成三模块联动。

## 4. 两项保持最优值的实现简化

### 精确等级区间替代 u

已知 z 恰有一个为 1，C8-C12 可以消去 u，直接使用：

`sum_k a[k]*z[t,k] <= N[t-1] <= sum_k h[k]*z[t,k]`，其中 k<10 时 `h[k]=min(Nmax,a[k+1]-1)`，k=10 时 `h[10]=Nmax`。

若 z[t,k]=1，便有 `a[k] <= N[t-1] <= h[k]`；反过来，整数 N 只能属于一个相邻门槛区间。这与原阈值逻辑的整数可行域相同，不允许提前升级。超出当天可达到累计上界的等级变量直接固定为 0。u 如需输出，可由 `u[t,k]=sum_{j>=k}z[t,j]` 恢复。

### 严格支配活动删列

仅比较相同季节、时段与等级下的活动。若替代活动的毛收入不低、开盘支出不高、时间和体力不高，而且在原活动可用的每种持竿状态下都可用，则逐竿替换不会破坏任何约束，也保持累计竿数及未来等级。于是删除被支配活动保留最优目标值；它不承诺保留每一个等价最优日程。

这里必须分别比较毛收入与成本，只比较净收入可能破坏 G5。吊钩损耗计入每竿成本；原始 CSV 不删除任何行。`--no-prune` 可关闭删列；测试已对两日完整/删列模型做最优值对照。完整 112 天未另跑不删列版本。

## 5. 输出和判断

| 输出 | 用法 |
| --- | --- |
| `summary.json` | 状态、期末现金、上界、gap、耗时、配置、购买日、100k 首次跨越日及输入 SHA256 |
| `daily_schedule.csv` | 112 日等级、竿数、购买、现金与四项 R/C/T/E 接口 |
| `activity_schedule.csv` | 每个非零日期—时段—地点—模式的整数竿数，可同一时段混用模式 |
| `validation.json` | 独立重算结果与检查次数 |
| `solver.log` | 求解器原始日志 |

出现 `Time limit` 时仅能称已找到可行方案，并报告剩余 gap。没有可行整数解时程序报错，不生成伪日程。LP 松弛仅导出 `lp_bound.json`，不把小数竿数作为操作建议。100,000g 日期只是期末最优路径的首次跨越时间，未对“最早达标”另行优化。

## 6. 联动边界

`build_model()` 当前构建独立现金与预算；日程中的 Revenue_g、Cost_g、Time_Min、Energy 对应 R/C/T/E。三模块联动还需将各自活动约束接入共同模型，只建一条全局现金路径及共同资源预算，不能把三个独立解相加。精确跨模块时段排程也需要共同时间窗；当前接口不是已求解的联合模型。
